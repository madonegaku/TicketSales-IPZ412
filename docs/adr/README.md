# Записи архітектурних рішень (ADR)

Кожен файл у цьому каталозі фіксує **одне** архітектурне рішення разом із контекстом, у якому воно ухвалене, розглянутими варіантами та наслідками (структура – за методичними вказівками до ЛР 1, рис. 1.2, та M. Nygard, *Documenting Architecture Decisions*).

| [ADR-002](0002-technology-stack.md) | Технологічний стек: Python, Django, PostgreSQL, Celery, Redis | Прийнято | 2026-10-29 | ЛР 1 |

## Правила ведення

1. **Нумерація послідовна:** файл `NNNN-коротка-назва.md`, де `NNNN` – наступний вільний номер (0003, 0004 …). Номери не використовуються повторно.
2. **Статуси:** `Запропоновано` → `Прийнято` → (за потреби) `Замінено ADR-00N` або `Відхилено`.
3. **Прийнятий запис не редагується заднім числом.** Якщо рішення переглянуто, створюється **новий** запис зі статусом «Прийнято» і полем «Замінює ADR-00N», а в старому записі змінюється **лише рядок статусу** на «Замінено ADR-00M». Текст контексту, варіантів і наслідків старого запису залишається без змін – так зберігається історія причин вибору.
4. Допускаються лише технічні виправлення, що не змінюють змісту (друкарські помилки, биті посилання).
5. Новий запис створюється за [шаблоном](template.md) і додається до реєстру вище.
