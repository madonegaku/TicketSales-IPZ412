# Зацікавлені сторони (ЛР 1)

> Розділ 3 звіту. Аналітик домену: Шавейко О.Л.

Система зачіпає інтереси восьми сторін. Найважливіші для архітектури атрибути: надійність продажу місць, продуктивність на старті продажу та безпека платежів.

## Перелік зацікавлених сторін та їхніх інтересів

| Зацікавлена сторона | Інтерес до системи | Найважливіший атрибут якості |
| --- | --- | --- |
| Покупець | Швидко знайти захід, обрати місця й гарантовано отримати квиток | Продуктивність |
| Організатор заходу | Продати максимум місць, жодного разу не продати одне місце двічі, отримувати звіти | Надійність |
| Контролер | Швидко пропускати глядачів і відсікати підроблені або повторні квитки | Продуктивність, безпека |
| Адміністратор платформи | Модерувати заходи, налаштовувати систему, вирішувати звернення | Підтримуваність |
| Власник платформи (замовник) | Комісія з продажів, висока конверсія, швидке додавання нових функцій | Підтримуваність |
| Платіжний провайдер (LiqPay) | Коректна інтеграція, перевірка підпису запитів, відсутність шахрайських операцій | Безпека |
| Регулятор (захист персональних даних, фіскалізація) | Законна обробка персональних даних, фіскальні чеки на кожен продаж і повернення | Безпека |
| Команда розробки та супроводу | Зрозумілий код, просте розгортання й налагодження | Підтримуваність |

## Суперечливі інтереси

| Сторони | Суть суперечності | Компроміс |
| --- | --- | --- |
| Покупець ↔ Організатор | Тривалість резервування: покупець хоче більше часу на оплату, організатор – якнайшвидше повертати неоплачені місця в продаж, особливо на старті продажу | Резервування на 15 хвилин з автоматичним звільненням |
| Власник платформи ↔ Платіжний провайдер і регулятор | Зручність проти безпеки: власник хоче мінімум кроків до оплати, безпека вимагає капчі, 3-D Secure, згоди на обробку даних; кожен крок знижує конверсію | reCAPTCHA лише на кроці резервування, 3-D Secure на стороні LiqPay |
| Власник платформи ↔ Регулятор | Обсяг даних: власник хоче зберігати якомога більше даних про покупців для маркетингу, регулятор вимагає мінімізації даних і явної згоди | Мінімальний набір даних для покупки, маркетинг – лише за окремою згодою |
| Покупець ↔ Організатор | Повернення квитків: покупець хоче повернути квиток у будь-який момент, організатор – обмежити повернення за кілька днів до заходу | Правила повернення задаються для заходу (див. [відкриті питання](risks-and-open-questions.md#відкриті-питання)) |
